01 需求背景

当前已有一个基于纯 Web 技术实现的看图应用原型（单页 HTML），支持 13+ 种图片格式的浏览、缩放、旋转、幻灯片等基础功能。但作为浏览器内运行的网页应用，存在以下根本性局限：

🔒 系统集成缺失

无法关联文件类型，用户双击图片仍打开系统默认查看器；无法注册右键菜单"用绿角犀看图打开"；无法在任务栏 Jumplist 中显示最近文件。

📂 文件系统受限

浏览器 File System Access API 兼容性有限（Firefox/Safari 不支持），用户每次需手动选择文件夹；无法监听文件夹变化自动刷新列表。

⚡ 性能瓶颈

百兆级大图在浏览器中加载卡顿严重；HEIC 解码依赖 CDN 动态加载 WASM，离线不可用；无法利用本地原生图像引擎加速。

🚫 用户体验割裂

需要先打开浏览器再输入网址；没有桌面快捷方式；无法最小化到系统托盘；缺少原生窗口标题栏与系统级全屏。

用户明确需求："做一款看图软件，能全面兼容的，学习一下看图王"并希望"开发成 EXE"。这意味着产品形态从 Web 原型升级为 原生 Windows 桌面应用，需解决系统集成、文件关联、性能优化和离线可用四大核心问题。

02 需求目标

安装包体积≤ 25MB
冷启动≤ 1.5s
10MB 图片打开≤ 0.3s
内存占用(空闲)≤ 80MB
支持格式≥ 30 种

核心目标是将现有 Web 原型封装为 Windows 桌面 EXE，同时实现看图王级别的系统集成与格式兼容能力。具体分为三个层面：

第一层：桌面化封装（必须完成）

将 Web 应用打包为独立 EXE，拥有原生窗口、桌面图标、系统托盘；安装后自动关联常见图片格式，用户双击图片即用本软件打开；支持完全离线运行，HEIC 解码库内置不依赖网络。

第二层：系统深度集成（必须完成）

文件类型关联（JPG/PNG/GIF/WebP/HEIC 等 ≥ 15 种扩展名）；Windows 资源管理器右键菜单"用绿角犀看图打开"；任务栏 Jumplist 显示最近浏览的图片；系统级全屏与多显示器支持。

第三层：能力增强（本期完成核心项）

利用原生能力扩展 Web 版无法实现的功能：批量格式转换、批量调整尺寸、图片信息 EXIF 读取、设为桌面壁纸、复制到剪贴板（原生级别）、快捷键自定义。安装包内置自动更新通道。

03 市场与竞品分析

看图软件市场呈现"老牌工具固化、用户不满现状"的格局。2345 看图王以 95+ 格式兼容和功能大杂烩占据国内大众市场，但广告推送和安装捆绑饱受诟病 [PM判断]；Honeyview 于 2024 年 6 月停止更新，漫画党失去纯净选择；Windows 自带照片查看器格式支持极少（HEIC/RAW/PSD/WebP 均不原生支持），用户被迫寻找第三方工具。

这留下了一个明确的市场空位：纯净无广告、格式全面、轻量快速、现代 UI 的看图工具。

竞品方法论总结：2345 看图王的成功在于格式兼容广度 + 系统集成深度（文件关联、资源管理器缩略图、右键菜单），其失败在于广告破坏体验。Honeyview 的优势在于纯净轻快，但停更后格式支持停滞。本品的差异化策略是：取看图王的系统集成能力，弃其广告商业模式；取 Honeyview 的纯净体验，补其停更后的格式空白；用现代 Web 技术栈实现跨平台潜力，同时保证桌面级原生体验。

04 技术方案选型

桌面化封装需要在 Electron 和 Tauri 之间做选择。核心考量因素：安装包体积、内存占用、原生能力访问、开发效率、生态成熟度。

推荐方案

Tauri

Rust 后端 + 系统 WebView 前端，不捆绑 Chromium

安装包体积3-8 MB
内存占用(空闲)40-60 MB
原生API访问Rust FFI，无限制
文件系统操作原生 Rust，高性能
自动更新内置 Updater
系统托盘内置支持
开发语言Rust + JS/TS
生态成熟度2.x 稳定版

Electron

Node.js 后端 + 内置 Chromium，最成熟的桌面方案

安装包体积60-150 MB
内存占用(空闲)120-200 MB
原生API访问Node.js，丰富
文件系统操作Node fs，高性能
自动更新electron-updater
系统托盘内置支持
开发语言JS/TS 全栈
生态成熟度非常成熟
选型结论：Tauri 2.x。 看图软件的核心诉求是轻量快速，安装包体积和内存占用直接影响用户第一印象。Tauri 的 3-8MB 安装包 vs Electron 的 60-150MB 是数量级差异。Rust 后端可无缝调用 libheif、libraw 等原生图像解码库，性能与 C++ 方案持平。前端直接复用现有 Web 原型代码，迁移成本极低。Tauri 2.x 的系统托盘、全局快捷键、文件关联插件已覆盖桌面应用全部刚需。

05 功能需求详情

5.1 系统集成层

这是桌面版区别于 Web 版的核心能力，决定了用户能否"双击图片就用本软件打开"。以下功能均由 Rust 后端通过 Windows API 实现，前端通过 IPC 调用。

文件类型关联

P0 必须

安装时自动将以下扩展名关联到绿角犀看图：JPG、JPEG、PNG、GIF、WebP、AVIF、BMP、ICO、SVG、HEIC、HEIF、TIFF、TIF、APNG、TGA、PSD。用户在资源管理器中双击这些文件时，直接用本软件打开。

首次启动时弹出关联确认对话框，列出所有可关联的格式，用户可全选或自选。设置页面提供"重新关联"和"取消关联"按钮。当检测到其他看图软件（如 2345 看图王）已关联相同格式时，提示用户"是否将绿角犀看图设为默认看图程序"。

关联通过写入 Windows 注册表 HKEY_CLASSES_ROOT\\.jpg\shell\open\command 实现，程序路径使用安装后的绝对路径。卸载时自动还原关联到系统默认值。

右键菜单集成

P0 必须

在 Windows 资源管理器中，对图片文件右键时显示"用绿角犀看图打开"菜单项。对文件夹右键时显示"用绿角犀看图浏览此文件夹"，点击后打开软件并自动加载该文件夹内所有图片。

菜单项通过注册表 HKEY_CLASSES_ROOT\SystemFileAssociations\image\shell\LvJiaoXiViewer 注册，带有软件图标。安装时写入，卸载时清除。右键菜单文本可配置（设置中可修改显示名称）。

系统托盘与窗口管理

P1 重要

最小化到系统托盘：点击窗口最小化按钮时，窗口隐藏到系统托盘区域而非任务栏。托盘图标使用软件 Logo，右键菜单包含"显示窗口"、"浏览图片"、"退出"三个选项。关闭按钮默认退出程序，但可在设置中改为"最小化到托盘"。

单实例运行：通过命名互斥锁确保只有一个程序实例运行。第二次启动时，如果已有实例运行，则将命令行参数（打开的文件路径）发送给已运行实例并激活窗口，而不是启动新进程。

多显示器支持：记住窗口在哪个显示器上最后关闭，下次启动在同一显示器恢复。窗口位置和大小持久化到配置文件。

任务栏 Jumplist

P2 增强

Windows 任务栏右键软件图标时，显示"最近浏览"列表（最多 10 张最近打开过的图片缩略图+文件名），点击直接打开该图片。同时显示"固定"区域，用户可将常用图片固定到 Jumplist 顶部。数据持久化到本地 SQLite 或 JSON 配置文件。

命令行启动

P1 重要

支持命令行参数启动：LvJiaoXiViewer.exe [文件路径] 直接打开指定图片；LvJiaoXiViewer.exe [文件夹路径] 浏览整个文件夹；LvJiaoXiViewer.exe --slideshow [文件夹路径] 直接进入幻灯片播放模式。命令行参数同时用于文件关联和右键菜单的调用入口。

5.2 核心看图引擎

看图引擎是产品核心，直接复用 Web 原型的功能逻辑，但通过 Rust 后端增强解码能力和性能。前端使用 <img> 标签 + CSS transform 实现 GPU 加速的缩放/旋转/翻转/平移，与 Web 版完全一致。

格式解码（全面兼容）

P0 必须

浏览器原生格式（前端直接渲染）：JPG、PNG、GIF、WebP、AVIF、SVG、BMP、ICO、APNG — 这些格式现代 WebView 均原生支持，无需后端介入。

需后端解码的格式（Rust 解码后转为 PNG/JPEG 传给前端）：

格式解码方案输出
HEIC / HEIFlibheif-rs (Rust 绑定 libheif)JPEG blob
RAW (CR2/NEF/ARW/DNG 等)libraw-rs (Rust 绑定 LibRaw)JPEG blob
TIFF / TIFtiff crate (纯 Rust)PNG blob
PSDpsd crate (纯 Rust 解析)PNG blob (合并图层)
TGAimage cratePNG blob

解码流程：前端通过 IPC 将文件路径发给 Rust 后端 → Rust 根据扩展名选择对应解码器 → 解码为位图 → 转为目标格式 blob → 通过 Tauri 协议返回前端 → 前端 <img> 加载 blob URL 显示。整个流程异步执行，UI 显示加载进度。

所有解码库编译为静态链接，内置在 EXE 中，完全离线可用，不依赖任何 CDN 或网络资源。

缩放系统

P0 必须

支持四种缩放方式：滚轮缩放（以鼠标位置为锚点，0.05x-50x 范围）、按钮缩放（+/- 按钮，每次 1.2 倍）、双击切换（适应窗口 ↔ 2.5x 放大）、键盘缩放（+/- 键）。缩放通过 CSS transform: scale() 实现，GPU 硬件加速，60fps 流畅。

缩放百分比实时显示在工具栏中央，点击百分比文字可切换"适应窗口"和"实际大小(100%)"。支持"适应窗口"模式：图片自动缩放至完全可见且不超出窗口边界。当窗口大小变化时（包括全屏切换），自动重新计算适应缩放比例。

放大超过 100% 时可启用 image-rendering: pixelated 保持像素清晰度（设置中可选"平滑"或"像素化"）。

旋转与翻转

P0 必须

左旋转 L / 右旋转 R，每次 90 度。水平翻转 H / 垂直翻转 V。旋转和翻转通过 CSS transform: rotate() scale() 组合实现，不修改原图数据，仅改变显示。切换到下一张图片时自动重置变换状态（设置中可开启"记住旋转状态"）。

读取 EXIF Orientation 标记：对于手机拍摄的照片，自动根据 EXIF 中的方向信息正向显示，无需手动旋转。EXIF 读取由 Rust 后端 kamadak-exif crate 完成。

拖拽平移

P0 必须

鼠标按住拖拽平移图片（transform: translate()），松开停止。支持触摸屏单指拖拽和双指捏合缩放（移动端手势）。当图片缩小到完全可见时，拖拽无效（因为没有溢出区域可平移）。

平移边界检测：图片不会被拖出可视区域之外（设置中可关闭边界限制，允许自由拖拽）。

5.3 浏览与导航

文件夹加载与文件遍历

P0 必须

打开单张图片时，自动加载同目录下所有支持的图片文件，形成可翻页的图片列表。打开文件夹时，递归遍历子目录（设置中可关闭递归），加载所有图片。

文件遍历由 Rust 后端的 std::fs 完成，性能远超浏览器 File System Access API。支持百万级文件目录的快速扫描（通过扩展名过滤，只收集图片文件）。扫描结果按文件名自然排序（数字感知排序：img2.jpg 排在 img10.jpg 前面）。

支持文件夹监听：当当前浏览的文件夹中有新增/删除图片时，自动刷新列表（通过 Rust 的 notify crate 监听文件系统事件）。

翻页与导航

P0 必须

五种翻页方式：键盘方向键（←/→ 或 PageUp/PageDown）、鼠标滚轮（Ctrl+滚轮 缩放，纯滚轮翻页 — 可在设置中互换）、两侧导航箭头按钮、鼠标边缘翻页（光标移到图片左/右边缘 60px 区域，光标变箭头，单击翻页）、底部缩略图栏直接点击跳转。

翻页循环：最后一张按"下一张"跳回第一张，第一张按"上一张"跳到最后一张（可在设置中关闭循环）。Home 跳到第一张，End 跳到最后一张。

翻页时显示淡入动画（0.3s），平滑过渡不突兀。

智能预加载

P1 重要

当前图片显示后，后台静默预加载前后各 2 张图片到内存缓存。用户翻页时如果目标图片已在缓存中，瞬间显示无加载延迟。缓存使用 LRU 策略，最多缓存 20 张解码后的图片，超出时淘汰最久未访问的。

预加载由 Rust 后端执行：异步读取文件 → 解码 → 转为 JPEG blob → 存入内存缓存。前端请求图片时，Rust 先查缓存，命中则直接返回，未命中则实时解码。

大图（>50MB）不预加载，仅在用户翻到时按需加载，避免内存暴涨。

缩略图导航栏

P0 必须

底部水平缩略图栏显示当前文件夹所有图片的缩略图，当前浏览的图片高亮显示（蓝色边框 + 发光效果）。缩略图由 Rust 后端生成（image crate 缩放至 80x80），缓存到临时目录，下次打开同文件夹时直接读取缓存。

缩略图栏可水平滚动，当前图片始终自动滚动到视口中央。每个缩略图显示序号（左上角）和格式标签（右下角）。支持点击缩略图直接跳转到该图片。缩略图栏可通过快捷键 Tab 显示/隐藏，全屏模式下 3 秒后自动隐藏。

幻灯片播放

P1 重要

按 S 启动幻灯片，自动进入全屏模式。播放间隔 1-20 秒可调（默认 5 秒），进度条在屏幕顶部显示当前图片剩余时间。支持暂停/继续（空格键或播放按钮）、手动上一张/下一张（方向键）。

转场特效：淡入淡出（默认）、左滑、右滑、上滑、下滑、缩放。可在设置中选择特效类型或关闭特效。按 Esc 退出幻灯片并退出全屏。

播放顺序：正序（默认）、倒序、随机。随机模式下不重复直到全部播放一遍。

5.4 图片处理工具

图片信息面板

P1 重要

按 I 切换信息浮层，显示：文件名、格式、尺寸（像素）、文件大小、修改时间、当前缩放比例。Rust 后端额外解析 EXIF 信息：相机型号、拍摄时间、光圈、快门、ISO、焦距、GPS 坐标（如有）。EXIF 信息以可折叠分组形式展示。

信息面板可拖拽移动位置（设置中可固定到右上角）。支持"复制信息"按钮，将图片信息以文本格式复制到剪贴板。

复制到剪贴板

P0 必须

Ctrl+C 将当前图片（含当前旋转/翻转状态）复制到系统剪贴板，可直接粘贴到 Word、微信、PPT 等应用中。Rust 后端通过 arboard crate 写入系统剪贴板，支持位图格式（BMP/DIB）和 PNG 格式。

复制时如果图片有旋转/翻转变换，先在 Rust 端渲染变换后的位图再写入剪贴板，确保粘贴结果与屏幕显示一致。

设为桌面壁纸

P2 增强

右键菜单或工具栏"设为壁纸"选项，调用 Windows SystemParametersInfo API 设置桌面壁纸。支持四种模式：居中、平铺、拉伸、适应。如果当前图片格式不被系统壁纸支持（如 HEIC/WEBP），Rust 后端先转为 JPG 存到临时目录再设置。

在资源管理器中显示

P1 重要

右键菜单"打开所在文件夹"，调用 explorer.exe /select,"文件路径" 在资源管理器中定位并选中当前图片文件。方便用户找到原图所在位置。

5.5 批量处理模块

批量处理是看图王的核心差异化功能之一，也是桌面应用相比 Web 版的重要能力补充。通过 Rust 后端的原生文件操作和图像处理能力实现。

批量格式转换

P1 重要

选中多张图片（或整个文件夹），一键转换为目标格式。支持的目标格式：JPG（质量 1-100 可调）、PNG（压缩级别 0-9）、WebP（质量 1-100）、BMP、TIFF。转换时保留 EXIF 信息（可选）。

输出文件命名规则：原名替换扩展名、添加后缀（如 photo_converted.jpg）、自定义前缀。输出目录：原目录、指定目录、子目录。转换进度条显示"3/50 已完成"，支持取消操作。转换完成后显示汇总报告（成功数、失败数、跳过数）。

Rust 后端使用 image crate 进行格式转换，利用多线程并行处理（Rayon 库），充分利用多核 CPU。50 张 5MB 图片转换在 3 秒内完成 [假设待验证]。

批量调整尺寸

P2 增强

按百分比缩放（10%-500%）或指定目标尺寸（宽x高，可锁定宽高比）。支持四种重采样算法：最近邻（最快）、双线性（平衡）、Lanczos（最高质量）、Catmull-Rom。可设置 DPI（72/96/150/300/600）。输出格式和质量可与批量转换联动配置。

批量重命名

P2 增强

支持模板化重命名：序号（{n}、{n:3} 零填充3位）、原文件名（{name}）、日期（{date}、{date:YYYYMMDD}）、自定义文本。预览区域实时显示重命名前后的文件名对比。支持撤销操作（记录原始文件名映射，一键还原）。

性能关键路径优化：大图加载是最大瓶颈。方案：Rust 后端在解码时生成渐进式 JPEG（先低分辨率预览，逐步清晰），前端先显示预览图再替换为全分辨率。同时利用 Rayon 多线程并行解码，image crate 的解码器已支持多线程。预加载缓存使用 Arc<Vec<u8>> 共享内存，避免数据拷贝。

07 打包与分发

安装包构建

使用 Tauri 内置的 tauri build 命令生成 NSIS 安装程序（.exe）和 MSI 安装包。安装包包含：

  • 主程序 LvJiaoXiViewer.exe（Tauri 编译产物，含 Rust 后端 + 前端资源）
  • 原生解码库（libheif、libraw 静态链接进 EXE，无额外 DLL）
  • 应用图标与资源文件
  • NSIS 安装脚本（注册文件关联、右键菜单、创建快捷方式）

自动更新

集成 Tauri Updater 插件，每次启动时静默检查 GitHub Releases 或自建更新服务器。检测到新版本时，弹窗提示"发现新版本 vX.X.X，是否立即更新？"，用户确认后下载增量更新包并自动安装。更新服务器返回 JSON 格式的版本信息：

{
  "version": "1.0.1",
  "notes": "修复 HEIC 解码问题，新增 AVIF 支持",
  "pub_date": "2026-08-15T10:00:00Z",
  "platforms": {
    "windows-x86_64": {
      "signature": "...",
      "url": "https://updates.example.com/v1.0.1/LvJiaoXiViewer-setup.exe"
    }
  }
}

数字签名

代码签名证书。使用 EV 代码签名证书对 EXE 和安装包进行数字签名，避免 Windows SmartScreen 拦截警告。签名后安装时显示发布者名称而非"未知发布者"。证书费用约 ¥2000-3000/年 [假设待验证]。
